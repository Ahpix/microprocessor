# 🎮 다마고치 하드웨어 조작기 개발 계획서

**담당자**: 이주형 (하드웨어 담당)  
**플랫폼**: **라즈베리파이 4 Model B** (Raspberry Pi OS / Python 3)  
**역할**: 물리 버튼 입력 감지 및 다마고치 상태 LED 출력을 담당하는 독립형 하드웨어 조작기 구현

---

## 1. 개요 및 설계 원칙

본 모듈은 라즈베리파이의 GPIO를 활용하여 다마고치 게임을 플레이할 수 있는 물리 조작기를 구성합니다.

> **핵심 설계 원칙: 책임의 분리 (Separation of Concerns)**
> - **하드웨어의 역할**: 물리 버튼의 누름을 감지하여 노이즈(채터링)를 제거한 뒤, **"어떤 버튼이 눌렸다"는 순수 이벤트만 게임 엔진으로 전달**합니다. 또한 게임 엔진으로부터 받은 명령에 따라 **LED 4개를 점등/소등/깜빡임**합니다.
> - **게임 엔진의 역할**: 전달받은 버튼 이벤트가 현재 모드(홈, 미니게임, 수면, 배틀 등)에서 어떤 행동(메뉴 이동, 먹이 주기, 공격 등)을 의미하는지 해석하고 게임 상태를 갱신합니다.

## 2. 하드웨어 구성 및 스펙

### 2.1 버튼 (3개)
다마고치 게임 메뉴 및 선택지를 탐색하고 결정하기 위한 물리 택트 스위치 3개로 구성됩니다.

| 버튼 명칭 | 기본 역할 | 프로토콜 매핑 | 상세 기능 |
|:---:|:---:|:---:|:---|
| **버튼 1** | **방향키 1 (이전 / 메뉴 이동)** | `Button A` | 선택지 이전/다음 순환 탐색 (Home: 메뉴 이동, Battle: 공격) |
| **버튼 2** | **선택 버튼 (결정 / 확인)** | `Button B` | 현재 선택된 메뉴/행동 확정 (Home: 선택/확인, Battle: 방어) |
| **버튼 3** | **방향키 2 (취소 / 뒤로가기)** | `Button C` | 메뉴 취소 또는 상태 보기 (Home: 취소/상태, Battle: 스킬) |

- **입력 처리 방식**:
  - 라즈베리파이 내부 풀업 저항(`PULL_UP`) 활성화 (버튼 누름 시 `LOW` 감지)
  - 채터링 방지를 위한 소프트웨어 디바운스(`bouncetime=200ms` 또는 30~50ms 타이머 검증) 적용
  - 한 번 누르면 단 1회의 `press` 이벤트만 발생 (길게 누름 시 자동 반복 금지)

### 2.2 상태 표시 LED (4개)
다마고치 캐릭터의 상태와 시스템 연결 상태를 직관적으로 확인할 수 있는 LED 4개로 구성됩니다. (전류 제한 저항 220Ω~330Ω 적용)

| LED 명칭 | 모니터링 대상 | 점등 (ON) 조건 | 깜빡임 (BLINK) 조건 | 소등 (OFF) 조건 |
|:---:|:---:|:---:|:---:|:---:|
| **LED 1** | **배고픔 (포만감, Satiety)** | 포만감 > 30% (충분) | 포만감 ≤ 30% (배고픔 경고) | 캐릭터 사망 또는 비활성 |
| **LED 2** | **행복도 (Happiness)** | 행복도 > 30% (양호) | 행복도 ≤ 30% (우울 경고) | 캐릭터 사망 또는 비활성 |
| **LED 3** | **에너지 (Energy)** | 에너지 > 30% (활력) | 에너지 ≤ 30% (피로/수면 필요) | 캐릭터 사망 또는 비활성 |
| **LED 4** | **서버 연결 (Connection)** | 서버/Unity 정상 연결 | 연결 끊김 / Heartbeat 이상 | 전원 종료 |

- **LED 제어 방식**:
  - `on`: 상시 점등
  - `off`: 소등
  - `blink`: 주기적 깜빡임 (기본 1000ms 주기, 50% 듀티비). 비동기 스레드로 독립 제어하여 메인 루프를 블로킹하지 않음.

## 3. 입출력 통신 인터페이스 규격

하드웨어와 게임 엔진/서버 간 주고받는 표준 메시지 형식입니다 (`docs/protocol.md` 준수).

### 3.1 버튼 입력 전송 (`button_event`)
버튼이 눌렸을 때 하드웨어에서 게임 엔진으로 전송하는 메시지:
```json
{
  "protocol_version": 1,
  "type": "button_event",
  "message_id": "pi01-hw-000001",
  "device_id": "pi01",
  "timestamp": 1794755306.665,
  "payload": {
    "button": "A",
    "event": "press"
  }
}
```

### 3.2 LED 제어 수신 (`led_command`)
게임 엔진에서 하드웨어로 전달하는 LED 상태 갱신 명령:
```json
{
  "protocol_version": 1,
  "type": "led_command",
  "message_id": "server-000042",
  "device_id": "pi01",
  "timestamp": 1794755307.000,
  "payload": {
    "leds": {
      "satiety": { "mode": "on" },
      "happiness": { "mode": "on" },
      "energy": { "mode": "blink", "period_ms": 1000 },
      "connection": { "mode": "on" }
    }
  }
}
```
